# 🧱 سیستم مدیریت شرکت تولیدی فردای روشن

برنامه دسکتاپ **ویندوز** برای شرکت تولیدی و فروشنده **سنگ، کرش، جغل، ریگ، ماسه و خاک** —
با **Tauri 2 + React + TypeScript** در محیط دسکتاپ، **API داخلی NestJS** و **Prisma + SQLite** روی همان کمپیوتر.

> **کاملاً محلی و آفلاین (Local):** برای فروش روزانه، ثبت مصارف، معاشات و راپورها
> **VPS، PostgreSQL، Docker یا انترنت لازم نیست.** هیچ درخواستی به بیرون فرستاده نمی‌شود
> (فونت‌ها داخل خود برنامه‌اند، هیچ CDN یا سرویس ابری استفاده نشده).

## ۱) شیت‌ها و امکانات

| شیت | محتوا |
|---|---|
| **مشخصات شرکت** (ثابت) | نام، نوع فعالیت، آدرس، سال مالی، مدیر مالی، سرپرست، تماس + **انواع و تعداد ماشینری** |
| **کارمندان** | شماره، کد کارمند، نام، نام پدر، وظیفه، تاریخ استخدام، معاش ثابت، شماره تماس، شماره تذکره، آدرس، مدت قرارداد، وضعیت (فعال/غیر فعال)، توضیحات + **پروفایل هر کارمند** |
| **حضور و غیاب** | نمای ماهانه گرافیکی (کلیک روی خانه‌ها)، ورق روزانه (حاضر/غایب/رخصت/مریض/رخصتی/جمعه + ساعت ورود و خروج + اضافه کاری)، خلاصه ماهانه |
| **فروشات** | شماره بل (خودکار)، تاریخ، کد/نام مشتری، نام دریور، پلیت موتر، مقصد، نوع مواد (کشویی)، **متراژ (م³)، قیمت فی متر، کرایه فی متر، مجموع کرایه، مجموع قیمت و کرایه**، مربوط (باربری/دمترک)، نوع پرداخت (نقده/باقی)، توضیحات + **چاپ بل فروش** |
| **مشتریان** | کد مشتری، نام مشتری/شرکت، شخص رابط، تماس، پلیت، **باقی مانده بدهی** (خودکار)، توضیحات + **کارت حساب با باقی مانده متحرک و چاپ** |
| **مصارف** | شماره، تاریخ، شرح، نوع مصرف، مربوط، نمبر بل خرید، نام فروشگاه، **مبلغ افغانی، مبلغ دالری**، پرداخت‌کننده، روش پرداخت (نقده/باقی)، توضیحات |
| **رسیدات** | شماره، تاریخ، کد/نام مشتری، مبلغ رسید، شماره بل مربوط، **از درک** (باقی داری/امانت/بیانیه/پیش‌پرداخت)، توسط، شرح |
| **معاشات** | **ورق ماهانه**: معاش ثابت، پاداش، جریمه، اضافه کاری (از حضور و غیاب خودکار)، مجموع پرداخت، پرداخت‌کننده، نوع پرداخت (نقد/حواله) + **رسید چاپی معاش** |
| **راپور روزانه** | فروشات قرضه، فروشات نقده، رسیدات، مصارف، پرداخت معاشات، مجموع مصارف، **موجودی دخل** (+ موجودی متحرک) |
| **راپور ماهانه** | فروشات نقده/قرضه، کل رسیدات، کل معاشات، کل مصارف، سود خالص، زیان |
| **راپور سالانه** | سال مالی، کل فروشات، کل مصارف، سود، زیان |
| **راپورهای تفصیلی** | فروشات به نوع مواد، فروشات به مشتری، مصارف به نوع/پرداخت‌کننده، کرایه به باربری، خلاصه معاشات، راپور بدهی همه مشتریان، **حرکت دخل** |

### امکانات اضافی

- **چاپ رسمی** (A4) با سرصفحه شرکت و جای امضا: بل فروش، رسید معاش، صورت حساب مشتری، راپورها.
- **خروجی اکسل (CSV)** از همه شیت‌ها — با BOM و UTF-8، در اکسل درست باز می‌شود.
- **پشتیبان‌گیری و بازگردانی** از داخل خود برنامه (بدون ابزار بیرونی) + فایل احتیاطی خودکار قبل از بازگردانی.
- **تقویم قابل تنظیم**: هجری شمسی یا میلادی — با یک کلیک کل سیستم عوض می‌شود (معلومات پاک نمی‌شود).
- **جداول کشویی قابل مدیریت**: اقلام و مواد، انواع مصرف، پرداخت‌کنندگان، منابع رسیدات، باربری‌ها —
  با ترتیب، فعال/غیرفعال، شمارش «استفاده در اسناد» و حذف امن.
- **جستجو، فلتر (بازه تاریخ، مشتری، نوع مواد، نوع پرداخت) و صفحه‌بندی** در همه شیت‌ها.
- **سابقه فعالیت** (چه کسی، چه وقت، چه تغییر داد).
- **چند کاربر** با دو سطح دسترسی: مدیر (کامل) و کارمند (ثبت/ویرایش بدون حذف و تنظیمات).
- **ظاهر قابل تنظیم**: روشن/تیره، ۸ رنگ، فشردگی، فونت، شماره‌گذاری ردیف‌ها — همه محلی.
- **آفلاین کامل**: فونت وزیرمتن داخل بسته است؛ هیچ درخواست بیرونی وجود ندارد.

## ۲) فرمول‌های حساب

| محاسبه | فرمول |
|---|---|
| مبلغ مواد | `متراژ × قیمت فی متر` |
| مجموع کرایه | `متراژ × کرایه فی متر` |
| مجموع بل فروش | `(متراژ × قیمت فی متر) + (متراژ × کرایه فی متر)` |
| مجموع پرداخت معاش | `معاش ثابت + پاداش + اضافه کاری − جریمه` |
| باقی مانده بدهی مشتری | `بدهی اولیه + مجموع فروشات قرضه − مجموع رسیدات (به جز امانت)` |
| مجموع مصارف (در راپور) | `مصارف + پرداخت معاشات` |
| سود / زیان خالص | `کل فروشات (نقده + قرضه) − (کل مصارف + کل معاشات)` |

**موجودی دخل — دو حالت در تنظیمات:**

1. **ساده (پیش‌فرض):** `فروشات نقده + رسیدات − همه مصارف − همه معاشات`
2. **دقیق:** فقط پولی که واقعاً از دخل آمده/رفته —
   `فروشات نقده + رسیدات − مصارف نقدی که پرداخت‌کننده‌اش «دخل» است − معاشات نقدی پرداخت‌شده از دخل`
   (مصارف «باقی» یا پرداخت‌شده توسط دیگران از دخل کم نمی‌شود)

**مبلغ دالری** در مصارف جداگانه نگهداری می‌شود (به افغانی تبدیل نمی‌شود) و سود/زیان فقط با افغانی حساب می‌شود.

**تاریخ‌ها** در دیتابیس به صورت میلادی (`YYYY-MM-DD`) ذخیره می‌شوند؛ ورود، نمایش و راپور ماهانه/سالانه
مطابق تقویم انتخابی سیستم (شمسی/میلادی) انجام می‌شود. ورود تاریخ با ارقام دری هم قبول است: `۱۴۰۵/۰۸/۱۹`.

## ۳) معماری

```
┌───────────────────────────────────────────────────────────────┐
│  پنجره دسکتاپ (Tauri 2 — Rust)                                │
│  • مسیر دیتابیس کاربر را تعیین می‌کند (FD_DATA_DIR)            │
│  • پروسه API محلی را استارت و با بستن برنامه خاموش می‌کند       │
└───────────────┬───────────────────────────────────────────────┘
                │  http://127.0.0.1:4317/api  (فقط روی همان کمپیوتر)
┌───────────────▼───────────────────────────────────────────────┐
│  WebView: React + TypeScript + Vite (راست‌چین، آفلاین)         │
└───────────────┬───────────────────────────────────────────────┘
┌───────────────▼───────────────────────────────────────────────┐
│  API داخلی: NestJS (Node)                                      │
│  • Auth محلی (session token)، نقش مدیر/کارمند                  │
│  • شماره سند خودکار، فرمول‌ها، راپورها، CSV، پشتیبان           │
└───────────────┬───────────────────────────────────────────────┘
┌───────────────▼───────────────────────────────────────────────┐
│  Prisma 7 (ORM) + driver adapter libsql  →  SQLite محلی        │
│  فایل: %APPDATA%\af.farday.roshan\farday.db                    │
└───────────────────────────────────────────────────────────────┘
```

- **Prisma** برای مدل داده و کوئری‌های تایپ‌شده (`apps/api/prisma/schema.prisma`، کلاینت در `apps/api/src/generated/prisma`).
- **SQLite محلی** با WAL؛ هیچ سرور دیتابیس جدا لازم نیست.
- ساختار جداول در `apps/api/src/schema.ts` آمده و **در اولین اجرا خودکار ساخته/ترمیم می‌شود**
  (نه به `prisma migrate` و انترنت نیاز دارد، نه به ابزار بیرونی).
- API روی `127.0.0.1:4317` گوش می‌دهد — از بیرون قابل دسترس نیست.

## ۴) اجرا (سه راه)

### الف) نسخه نصب‌شده (برای شرکت — ساده‌ترین)

فایل نصب `Farday Roshan_x64-setup.exe` را روی کمپیوتر اجرا کنید. تمام — نه Node لازم است، نه دیتابیس، نه انترنت.
دیتابیس در `%APPDATA%\af.farday.roshan\` ساخته می‌شود.

### ب) حالت توسعه (برای برنامه‌نویس)

نیازمندی‌ها: **Node 22+**، **Rust** (برای دسکتاپ) و در ویندوز **WebView2** (در ویندوز ۱۰/۱۱ از قبل موجود است).

```bash
npm install

# ۱) حالت وب (سریع‌ترین برای کار روی UI)
npm run dev          # API روی 4317 + وب روی 5173  →  http://localhost:5173

# ۲) اطلاعات نمونه (۲۰ کارمند، فروشات، مصارف، معاشات…)
npm run seed:demo

# ۳) پنجره دسکتاپ واقعی (Tauri)
npm run desktop:dev
```

نام کاربری پیش‌فرض: **admin** — رمز: **admin123** (بعد از ورود از تنظیمات عوض کنید).

### ج) ساخت نصب‌کننده ویندوز

```bash
npm install
npm run package:api      # API + node.exe را آماده می‌کند  (نیاز به انترنت فقط همین یک بار)
npm run desktop:build    # خروجی: src-tauri/target/release/bundle/nsis/*.exe
```

نصب‌کننده به صورت **per-user** نصب می‌شود (نیاز به دسترسی مدیر ویندوز ندارد).

## ۵) خط فرمان (بدون UI)

```bash
cd apps/api
node dist/cli/seed.js --demo          # معلومات نمونه
node dist/cli/seed.js                 # فقط فهرست‌ها + کاربر مدیر
node dist/cli/backup.js               # پشتیبان تازه  (--list برای فهرست)
node dist/cli/reset.js --status       # شمارش ردیف‌های هر جدول
node dist/cli/reset.js --yes          # پاک کردن معلومات کاری
node dist/cli/reset.js --yes --keep-masters   # فقط اسناد، کارمندان و مشتریان بمانند
```

> برای پشتیبان خودکار روزانه در ویندوز: **Task Scheduler** → روزانه → اجرا:
> `node "...\apps\api\dist\cli\backup.js"`

## ۶) امنیت و نکات فنی

- رمزها با **SHA-256 + salt** ذخیره می‌شوند؛ نشست‌ها در حافظه و با انقضای ۱۲ ساعته.
- API فقط روی **127.0.0.1** گوش می‌دهد (از شبکه بیرون قابل دسترس نیست).
- همه کوئری‌ها **پارامتری** (`$queryRawUnsafe` با placeholder) اجرا می‌شوند — محافظت از SQL Injection.
- نقش **کارمند** به حذف، تنظیمات، کاربران و پشتیبان دسترسی ندارد (کنترل سمت سرور).
- شماره اسناد (فروش، مصرف، رسید، معاش) **خودکار** و بدون تکرار ساخته می‌شود.
- هر عملیات مهم در `ActivityLog` ثبت می‌شود.
- هیچ درخواست بیرونی وجود ندارد — برای کمپیوتر بدون انترنت آزمایش شده.

## ۸) تغییرات آینده

ساختار آماده است: یک مدل در `apps/api/prisma/schema.prisma` + یک جدول در `apps/api/src/schema.ts`
+ یک کنترولر در `apps/api/src/modules/` + یک صفحه در `apps/web/src/pages/`.
برای اسناد تازه (خرید مواد خام، قراردادها، حضور و غیاب ماشینری) نیازی به تغییر معماری نیست.
