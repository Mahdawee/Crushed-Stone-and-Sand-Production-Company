# 🧱 سیستم مدیریت شرکت تولیدی فردای روشن

برنامه دسکتاپ **ویندوز** برای شرکت تولیدی و فروشنده **سنگ، کرش، جغل، ریگ، ماسه و خاک** —
با **Tauri 2 + React + TypeScript** در محیط دسکتاپ، **API داخلی NestJS** و **Prisma + SQLite** روی همان کمپیوتر.

> **کاملاً محلی و آفلاین (Local):** برای فروش روزانه، ثبت مصارف، معاشات و راپورها
> **VPS، PostgreSQL، Docker یا انترنت لازم نیست.** هیچ درخواستی به بیرون فرستاده نمی‌شود
> (فونت‌ها داخل خود برنامه‌اند، هیچ CDN یا سرویس ابری استفاده نشده).

| **حضور و غیاب** | نمای ماهانه گرافیکی (کلیک روی خانه‌ها)، ورق روزانه (حاضر/غایب/رخصت/مریض/رخصتی/جمعه + ساعت ورود و خروج + اضافه کاری)، خلاصه ماهانه |

| **راپور سالانه** | سال مالی، کل فروشات، کل مصارف، سود، زیان |
| **راپورهای تفصیلی** | فروشات به نوع مواد، فروشات به مشتری، مصارف به نوع/پرداخت‌کننده، کرایه به باربری، خلاصه معاشات، راپور بدهی همه مشتریان، **حرکت دخل** |

### امکانات اضافی

- **چاپ رسمی** (A4) با سرصفحه شرکت و جای امضا: بل فروش، رسید معاش، صورت حساب مشتری، راپورها.
- **خروجی اکسل (CSV)** از همه شیت‌ها — با BOM و UTF-8، در اکسل درست باز می‌شود.
- **پشتیبان‌گیری و بازگردانی** از داخل خود برنامه (بدون ابزار بیرونی) + فایل احتیاطی خودکار قبل از بازگردانی.
- **تقویم قابل تنظیم**: هجری شمسی یا میلادی — با یک کلیک کل سیستم عوض می‌شود (معلومات پاک نمی‌شود).
- **جداول کشویی قابل مدیریت**: اقلام و مواد، انواع مصرف، پرداخت‌کنندگان، منابع رسیدات، باربری‌ها —
  با ترتیب، فعال/غیرفعال، شمارش «استفاده در اسناد» و حذف امن.
- **جستجو، فلتر (بازه تاریخ، مشتری، نوع مواد، نوع پرداخت) و صفحه‌بندی** در همه شیت‌ها.
- **سابقه فعالیت** (چه کسی، چه وقت، چه تغییر داد).
- **چند کاربر** با دو سطح دسترسی: مدیر (کامل) و کارمند (ثبت/ویرایش بدون حذف و تنظیمات).
- **ظاهر قابل تنظیم**: روشن/تیره، ۸ رنگ، فشردگی، فونت، شماره‌گذاری ردیف‌ها — همه محلی.
- **آفلاین کامل**: فونت وزیرمتن داخل بسته است؛ هیچ درخواست بیرونی وجود ندارد.

## ۲) فرمول‌های حساب

| محاسبه | فرمول |
|---|---|
| مبلغ مواد | `متراژ × قیمت فی متر` |
| مجموع کرایه | `متراژ × کرایه فی متر` |
| مجموع بل فروش | `(متراژ × قیمت فی متر) + (متراژ × کرایه فی متر)` |
| مجموع پرداخت معاش | `معاش ثابت + پاداش + اضافه کاری − جریمه` |
| باقی مانده بدهی مشتری | `بدهی اولیه + مجموع فروشات قرضه − مجموع رسیدات (به جز امانت)` |
| مجموع مصارف (در راپور) | `مصارف + پرداخت معاشات` |
| سود / زیان خالص | `کل فروشات (نقده + قرضه) − (کل مصارف + کل معاشات)` |

**موجودی دخل — دو حالت در تنظیمات:**

1. **ساده (پیش‌فرض):** `فروشات نقده + رسیدات − همه مصارف − همه معاشات`
2. **دقیق:** فقط پولی که واقعاً از دخل آمده/رفته —
   `فروشات نقده + رسیدات − مصارف نقدی که پرداخت‌کننده‌اش «دخل» است − معاشات نقدی پرداخت‌شده از دخل`
   (مصارف «باقی» یا پرداخت‌شده توسط دیگران از دخل کم نمی‌شود)

**مبلغ دالری** در مصارف جداگانه نگهداری می‌شود (به افغانی تبدیل نمی‌شود) و سود/زیان فقط با افغانی حساب می‌شود.

**تاریخ‌ها** در دیتابیس به صورت میلادی (`YYYY-MM-DD`) ذخیره می‌شوند؛ ورود، نمایش و راپور ماهانه/سالانه
مطابق تقویم انتخابی سیستم (شمسی/میلادی) انجام می‌شود. ورود تاریخ با ارقام دری هم قبول است: `۱۴۰۵/۰۸/۱۹`.

## ۳) معماری

```
┌───────────────────────────────────────────────────────────────┐
│  پنجره دسکتاپ (Tauri 2 — Rust)                                │
│  • مسیر دیتابیس کاربر را تعیین می‌کند (FD_DATA_DIR)            │
│  • پروسه API محلی را استارت و با بستن برنامه خاموش می‌کند       │
└───────────────┬───────────────────────────────────────────────┘
                │  http://127.0.0.1:4317/api  (فقط روی همان کمپیوتر)
┌───────────────▼───────────────────────────────────────────────┐
│  WebView: React + TypeScript + Vite (راست‌چین، آفلاین)         │
└───────────────┬───────────────────────────────────────────────┘
┌───────────────▼───────────────────────────────────────────────┐
│  API داخلی: NestJS (Node)                                      │
│  • Auth محلی (session token)، نقش مدیر/کارمند                  │
│  • شماره سند خودکار، فرمول‌ها، راپورها، CSV، پشتیبان           │
└───────────────┬───────────────────────────────────────────────┘
┌───────────────▼───────────────────────────────────────────────┐
│  Prisma 7 (ORM) + driver adapter libsql  →  SQLite محلی        │
│  فایل: %APPDATA%\af.farday.roshan\farday.db                    │
└───────────────────────────────────────────────────────────────┘
```

- **Prisma** برای مدل داده و کوئری‌های تایپ‌شده (`apps/api/prisma/schema.prisma`، کلاینت در `apps/api/src/generated/prisma`).
- **SQLite محلی** با WAL؛ هیچ سرور دیتابیس جدا لازم نیست.
- ساختار جداول در `apps/api/src/schema.ts` آمده و **در اولین اجرا خودکار ساخته/ترمیم می‌شود**
  (نه به `prisma migrate` و انترنت نیاز دارد، نه به ابزار بیرونی).
- API روی `127.0.0.1:4317` گوش می‌دهد — از بیرون قابل دسترس نیست.
- باز کردن آدرس `/api` در مرورگر، به جای خطای `Cannot GET /api`، یک صفحه راهنما نشان می‌دهد
  («این سرویس داخلی است — خود برنامه در آدرس `/` است») با دکمه «رفتن به برنامه» و فهرست آدرس‌ها.
  برای کلاینت‌های برنامه‌نویسی، همان آدرس JSON برمی‌گرداند.
- اگر رابط ساخته نشده باشد (`apps/web/dist` خالی)، آدرس `/` صفحه‌ای با عنوان
  «رابط کاربری ساخته نشده» و راه‌حل `npm run build` نشان می‌دهد — به جای JSON خام
  `Cannot GET /`. آدرس‌های ناموجود (`/api/...`) هم در مرورگر همان صفحه راهنما را می‌دهند.

## ۳-۱) تقویم شمسی در همه فرم‌ها

هر جا تاریخ لازم است، به جای فیلد متنی ساده یک **تقویم شمسی (DatePicker)** هست:

- کلیک روی آیکن تقویم → شبکه ماه (هفته از **شنبه**)، انتخاب ماه و سال، دکمه «امروز»، «−۱ روز»، «+۱ روز»
- تایپ دستی هم کار می‌کند: `۱۴۰۵/۰۸/۱۹` یا `1405/8/19` (ارقام دری و انگلیسی)
- `Enter` تأیید، `Esc` لغو، `✕` پاک کردن (در نوار فیلترها)
- خروجی همیشه **ISO میلادی** برای دیتابیس است؛ نمایش همیشه با تقویم انتخاب‌شده (پیش‌فرض شمسی)
- برای ماه‌ها (معاش، حضور و غیاب، راپور ماهانه) از انتخابگر ماه/سال استفاده می‌شود

> قاعده مهم API: هر رشته تاریخ به شکل `YYYY-MM-DD` **همیشه میلادی** تفسیر می‌شود؛
> تاریخ با اسلش (`1405/08/19`) در تقویم فعال سیستم خوانده می‌شود.
> بازه‌های راپور حداکثر ۴۰۰ روز هستند و بازه معکوس با پیام دری رد می‌شود.

## ۴) اجرا (سه راه)

### الف) نسخه نصب‌شده (برای شرکت — ساده‌ترین)

فایل نصب `Farday Roshan_x64-setup.exe` را روی کمپیوتر اجرا کنید. تمام — نه Node لازم است، نه دیتابیس، نه انترنت.
دیتابیس در `%APPDATA%\af.farday.roshan\` ساخته می‌شود.

### ب) حالت توسعه (برای برنامه‌نویس)

نیازمندی‌ها: **Node 22+**، **Rust** (برای دسکتاپ) و در ویندوز **WebView2** (در ویندوز ۱۰/۱۱ از قبل موجود است).

```bash
npm run setup        # نصب بسته‌ها + build (بعد از هر git pull همین را بزنید)

# ۱) اجرا در یک آدرس واحد  →  http://127.0.0.1:4317
npm start

# ۲) حالت توسعه با hot-reload  →  http://localhost:5173
npm run dev

# ۳) اطلاعات نمونه (۲۰ کارمند، فروشات، مصارف، معاشات…)
npm run seed:demo

# ۴) ساخت نصب‌کننده ویندوز (یک دستور، هر سه مرحله)
npm run desktop:build
```

**بعد از هر `git pull` (به‌ترتیب):**

| هدف | دستورها |
|---|---|
| فقط اجرا/دیدن برنامه | `npm run setup` → `npm start` |
| کار روی ظاهر/کد | `npm run setup` → `npm run dev` |
| ساخت نصب‌کننده | `npm run setup` → `npm run desktop:build` |
| اگر `package.json` عوض شده | `npm install` → `npm run desktop:build` |
| ساخت خطا داد | `npm run doctor` (راه‌حل هر مورد را فارسی می‌گوید) |

`npm run setup` خودش تشخیص می‌دهد چه چیزی کهنه است (بسته‌ها/API/رابط) و بقیه را رد می‌کند.

نام کاربری پیش‌فرض: **admin** — رمز: **admin123** (بعد از ورود از تنظیمات عوض کنید).

> `npm run dev` یک کارت شروع چاپ می‌کند: **رابط کاربری** روی `http://localhost:5173` (با hot-reload)،
> **سرویس** روی `http://127.0.0.1:4317/api`. اگر پورت‌ها مشغول بودند: `FD_PORT` و `FD_WEB_PORT`.
> در حالت توسعه، پورت ۴۳۱۷ رابط کاربری را سرو نمی‌کند (آن کار Vite است) — باز کردن `127.0.0.1:4317`
> عمداً صفحه «این آدرس سرویس است، برنامه اینجاست» را نشان می‌دهد.

### ج) ساخت نصب‌کننده ویندوز

```bash
npm run doctor           # بررسی پیش‌نیازها با پیام دری
npm run desktop:build    # خروجی: src-tauri/target/release/bundle/nsis/*.exe
```

نصب‌کننده به صورت **per-user** نصب می‌شود (نیاز به دسترسی مدیر ویندوز ندارد).
راهنمای کامل و گام‌به‌گام: **[`docs/TAURI-BUILD.md`](docs/TAURI-BUILD.md)**

## ۴-۱) نصب و ساخت نسخه دسکتاپ (Tauri) — گام‌به‌گام

> این بخش را یک بار روی کمپیوتر **برنامه‌نویس** انجام دهید تا فایل `.exe` ساخته شود.
> کمپیوتر شرکت فقط همان فایل نصب را می‌خواهد (نه Rust، نه Node).

### گام ۰ — بررسی خودکار محیط

```bash
npm run doctor
```
اگر همه موارد ✔ شد، به گام ۵ بروید. هر مورد ✘ راه‌حل خودش را نشان می‌دهد.

### گام ۱ — Node.js

از <https://nodejs.org> نسخه **LTS 22** را نصب کنید (نه نسخه عجیب/قدیمی).
بررسی: `node -v` → باید `v22.x` یا بالاتر باشد.

### گام ۲ — Rust

| ویندوز | لینوکس / مک |
|---|---|
| از <https://rustup.rs> فایل `rustup-init.exe` را اجرا کنید (گزینه ۱ = پیش‌فرض) | `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs \| sh` |
| یا در PowerShell: `winget install Rustlang.Rustup` | سپس: `source "$HOME/.cargo/env"` |

بعد از نصب، **ترمینال را ببندید و دوباره باز کنید** و بررسی کنید:
```
rustc --version      →  rustc 1.7x.x
cargo --version
```
> اگر `rustc` شناخته نشد، یعنی متغیر PATH تازه نشده — ویندوز را یک بار Log off/on کنید.

### گام ۳ — ابزارهای ساخت (Windows)

Tauri برای لینک کردن به کامپایلر C++ نیاز دارد:

1. **Visual Studio Build Tools** را از
   <https://visualstudio.microsoft.com/visual-cpp-build-tools/> دانلود و نصب کنید.
2. در نصب، تیک **«Desktop development with C++»** را بزنید (شامل MSVC و Windows SDK).
3. نیازی به Visual Studio کامل نیست؛ همین Build Tools کافی است.

> **WebView2**: در ویندوز ۱۰/۱۱ از قبل نصب است. اگر نبود، از
> <https://developer.microsoft.com/microsoft-edge/webview2/> نصب کنید — نصب‌کننده نهایی هم
> در صورت نبود، خودش لینک دانلود را نشان می‌دهد.

**لینوکس (اوبونتو/دبیان)** — یک دستور:
```bash
sudo apt update && sudo apt install -y build-essential curl wget file \
  libwebkit2gtk-4.1-dev libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

### گام ۴ — بسته‌های پروژه و ابزار Tauri

```bash
npm install                # @tauri-apps/cli حالا جزو devDependencies است و با همین نصب می‌آید
npx tauri --version        # باید ۲.x چاپ شود
```
> `npm run desktop:setup` هم هنوز کار می‌کند (همان بسته را دوباره نصب می‌کند)؛ اگر خواستید
> بدون npm بسازید: `cargo install tauri-cli --version "^2"` و سپس `cargo tauri dev` / `cargo tauri build`.
>
> ⚠ اگر `cargo` در PATH نباشد، همان `npx tauri build` هم با خطای
> `failed to run 'cargo metadata' … program not found` می‌شکند — **همیشه از
> `npm run desktop:build` استفاده کنید** (خودش cargo را پیدا می‌کند).

> **آیا نصب Tauri ضروری است؟** برای **استفاده روزمره نه**. خود اپ وب + API محلی همین حالا کار می‌کند
> (`npm run dev` یا `npm run build && npm start` → <http://127.0.0.1:4317>). Tauri فقط برای ساختن
> **نصب‌کننده ویندوز/دبیان** لازم است، یعنی وقتی می‌خواهید فایل `*-setup.exe` را روی کمپیوتر شرکت ببرید.
> اگر کاربر همان کمپیوتر را با مرورگر باز می‌کند، از این مرحله‌ها رد شوید.

### گام ۵ — اجرای حالت دسکتاپ (آزمایش)

```bash
npm run desktop:dev
```
این دستور: رابط را build می‌کند → پروسه API محلی را استارت می‌کند → پنجره برنامه را باز می‌کند.
اولین اجرا چند دقیقه طول می‌کشد (کامپایل Rust).

### گام ۶ — ساخت نصب‌کننده

```bash
npm run desktop:build
```
این دستور سه کار می‌کند:
1. `build:desktop` → API و رابط کاربری را از کد فعلی می‌سازد.
2. `package:api` → فایل‌های API + `node.exe` (نسخه پرتابل ویندوز) + رابط build شده را در
   `src-tauri/api/` می‌گذارد تا **کمپیوتر شرکت به Node نیاز نداشته باشد**.
3. `tauri build` → نصب‌کننده را می‌سازد.

> **خطای `failed to run 'cargo metadata' … program not found`؟**
> یعنی Rust نصب نیست یا در PATH نیست. `npm run desktop:build` خودش این را
> تشخیص می‌دهد، مسیر `%USERPROFILE%\.cargo\bin` را در PATH همان اجرا می‌گذارد،
> و اگر Rust نبود دستور نصب می‌دهد. راه دستی: `npm run doctor` یا
> `scripts\install-rust.ps1` (راست‌کلیک → Run with PowerShell).
> جزئیات: `docs/TAURI-BUILD.md` بخش ۲/۱ و ۱۳.

خروجی‌ها:

| فایل | مسیر |
|---|---|
| **نصب‌کننده ویندوز (پیشنهادی)** | `src-tauri/target/release/bundle/nsis/Farday Roshan_0.1.0_x64-setup.exe` |
| نصب‌کننده MSI | `src-tauri/target/release/bundle/msi/*.msi` |
| نسخه بدون نصب (exe تنها) | `src-tauri/target/release/farday-roshan.exe` (کنارش پوشه `api/` لازم است) |
| لینوکس | `src-tauri/target/release/bundle/deb/*.deb` و `.../appimage/*.AppImage` |

> **برای توزیع به کمپیوتر شرکت:** فقط فایل `*-setup.exe` را کپی کنید. همین.

### گام ۷ — ساخت نصب‌کننده بدون انترنت

Tauri در اولین ساخت، crateهای Rust را از اینترنت می‌گیرد. برای ساخت **کاملاً آفلاین**:

1. روی یک کمپیوتر با انترنت: `npm ci` و بعد `npm run desktop:prefetch`
   (این دستور `cargo fetch` را اجرا می‌کند و همه crateها را در `.cargo` ذخیره می‌کند).
2. پوشه‌های `.cargo` و `.rustup` و `src-tauri/target` (اختیاری) و `node_modules` را به همان
   مسیرها در کمپیوتر آفلاین کپی کنید.
3. فایل ZIP نود را هم یک بار بگیرید: `https://nodejs.org/dist/v22.x/node-v22.x-win-x64.zip`
4. در کمپیوتر آفلاین:
   ```powershell
   npm run desktop:build:offline -- "D:\node-v22.x-win-x64.zip"
   ```
   یا اگر `node.exe` از قبل داخل `src-tauri/api` هست: `npm run desktop:build --offline`.

توضیح کامل: `docs/TAURI-BUILD.md` بخش ۸.

نصب‌کننده ساخته‌شده، خودش **هیچ نیازی به انترنت ندارد** — این محدودیت فقط برای مرحله ساخت است.

### خطاهای رایج و راه‌حل

| خطا | علت | راه‌حل |
|---|---|---|
| `error: linker `link.exe` not found` | Build Tools نصب نیست | گام ۳ را انجام دهید |
| `failed to run custom build command for ... webkit` | بسته‌های سیستمی لینوکس کم است | دستور `apt install` در گام ۳ |
| `'cargo' is not recognized` | PATH تازه نشده | ترمینال/ویندوز را ببندید و باز کنید |
| `failed to run 'cargo metadata' … program not found` | Rust نصب نیست، یا نصب است و در PATH نیست | `npm run desktop:build` (خودش PATH را درست می‌کند) یا `scripts\install-rust.ps1` — بخش ۲/۱ و ۱۳ همان راهنما |
| `API entry not found ...` هنگام اجرا | API build نشده | `npm run build -w @farday/api` |
| `node.exe not found` در نصب‌شده | بدون `package:api` ساخته شده | `npm run desktop:build` (هر سه مرحله را خودش انجام می‌دهد) |
| پنجره سفید می‌ماند | API دیر شروع شده | ۱۰ ثانیه صبر؛ `npm run doctor` و `dist` را بررسی کنید |
| `EADDRINUSE: 4317` | یک نسخه دیگر در حال اجراست | برنامه قبلی یا `node apps/api/dist/main.js` را ببندید |

## ۶) امنیت و نکات فنی

- رمزها با **SHA-256 + salt** ذخیره می‌شوند؛ نشست‌ها در حافظه و با انقضای ۱۲ ساعته.
- API فقط روی **127.0.0.1** گوش می‌دهد (از شبکه بیرون قابل دسترس نیست).
- همه کوئری‌ها **پارامتری** (`$queryRawUnsafe` با placeholder) اجرا می‌شوند — محافظت از SQL Injection.
- نقش **کارمند** به حذف، تنظیمات، کاربران و پشتیبان دسترسی ندارد (کنترل سمت سرور).
- شماره اسناد (فروش، مصرف، رسید، معاش) **خودکار** و بدون تکرار ساخته می‌شود.
- هر عملیات مهم در `ActivityLog` ثبت می‌شود.
- هیچ درخواست بیرونی وجود ندارد — برای کمپیوتر بدون انترنت آزمایش شده.
