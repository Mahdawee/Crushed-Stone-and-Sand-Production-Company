## ب) معماری در یک نگاه

```
مالک (شما)                     مشتری (ویندوز، آفلاین)
─────────                      ─────────────────────
npm run license:keygen          صفحه‌ی لایسنس: کلید دستگاه را کاپی می‌کند
  ↓ private.key (مخفی)                       ↓
npm run license:issue  ── متن امضاشده ──►  در کادر لایسنس می‌گذارد → فعال‌سازی
  ↓ public.key                                 ↓
داخل بسته (src-tauri/public-key)            API با کلید عمومی امضا را می‌سنجد
                                            + قفل دستگاه + قفل ساعت
```

هیچ سرور، هیچ انترنت، هیچ تماس تلفنی با سرور: تأیید امضا روی همان کمپیوتر و
در Node انجام می‌شود.

## ج) قالب متن لایسنس

```
-----BEGIN FARDAY LICENSE-----
FR-1
<base64url(payload)>
<base64url(Ed25519 signature over the base64url payload)>
-----END FARDAY LICENSE-----
```

بدنه: `{v,id,customer,kind,start,end,machineKey,seats,note,issuedAt}`.
امضا روی **رشته‌ی base64** زده می‌شود تا بازسازی JSON هیچ‌وقت باعث اختلاف نشود.

## د) سه لایه‌ی محافظت

1. **امضا** — هر تغییری در متن باطل می‌شود؛ بدون کلید خصوصی نمی‌شود لایسنس ساخت.
2. **قفل دستگاه** — `machineKey` از `MachineGuid` ویندوز + UUID تخته‌مادر +
   نام کمپیوتر/کاربر (فقط هش ۲۵ نویسه‌ای بیرون می‌رود) ساخته می‌شود.
3. **قفل ساعت** — مرجع = بزرگ‌ترین زمانی که دیده شده؛ فاصله‌ی بیش از ۲۴ ساعت
   (جلو یا عقب) = قفل + پیام فارسی. «اکنون» هرگز از مرجع عقب‌تر حساب نمی‌شود،
   پس عقب‌بردن ساعت لایسنس منقضی را زنده نمی‌کند. رکورد در دیتابیس و فایل،
   هر دو با HMAC.

صداقت فنی: برنامه‌ی نصب‌شده در برابر **وصله‌کردن باینری** مطلقاً مصون نیست؛
هدف این است که دور زدن نیازمند دست‌کاری فنی فایل اجرایی باشد، نه یک کلیک.

# دور یازدهم — سخت‌سازی + ابزار گرافیکی

## الف) پاسخ به «می‌شود دور زد؟»
بند **ط** در `docs/LICENSE.md`. خلاصه: همه‌ی راه‌های غیرفنی (تغییر متن، کاپی
دستگاه، ساعت، پاک‌کردن فایل‌ها، عوض‌کردن فایل کلید، متغیر محیطی) بسته‌اند؛
تنها راه باقی‌مانده **وصله‌کردن فایل اجرایی** است و برای تنگ‌کردن همان:

1. **مُهر کلید عمومی در باینری** — `src-tauri/build.rs` کلید را (XOR + اثر
   انگشت SHA-256) داخل `seal.rs` می‌پزد؛ `seal.rs` در زمان اجرا اثر انگشت را
   می‌سنجد و از راه `FD_SEALED_PUBLIC_KEY` به سرویس می‌دهد. عوض‌کردن کلید
   دیگر «ویرایش Notepad» نیست.
2. **بستن درهای پشتی** — `FD_MACHINE_KEY` و `FD_LICENSE_PUBLIC_KEY` فقط با
   `FD_LICENSE_DEV=1` اثر دارند (در نسخه‌ی نصب‌شده وجود ندارد).
3. **حذف مسیر پوشه‌ی داده** — برنامه هیچ کلید عمومی از پوشه‌ای که کاربر
   می‌تواند بنویسد نمی‌خواند (`shippedKeyPaths()`).

## ب) ابزار گرافیکی لایسنس
`npm run license:ui` → `http://127.0.0.1:4321`، صفحه‌ی فارسی/RTL با چهار بخش:
کلیدها، صدور، دفتر لایسنس‌ها، بازرسی. سرور فقط روی loopback، بدون بازگرداندن
کلید خصوصی، با توکن CSRF و بررسی مبدأ، و محافظت از path traversal.
(با curl واقعی آزموده شد: صدور ✅، بازرسی متن معتبر ✅، رد متن دست‌کاری‌شده ✅،
بدون توکن ❌ ۴۰۰، مبدأ خارجی ❌، `../etc/passwd` ❌.)

## ج) فایل‌های در گیت
کلیدها و لایسنس‌های صادرشده **کامیت نمی‌شوند** (`license-keys/` در
`.gitignore`). آنچه در گیت است فقط کلید **عمومی** است:
`src-tauri/public-key/`, `src-tauri/seal/public-key.txt`, `apps/api/public-key/`.
