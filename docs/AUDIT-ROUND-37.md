# دور ۳۷ — بازرسی «نیمه‌کاره مانده؟» و تست‌هایی که به وضعیت محلی وابسته بودند

تاریخ: ۲۰۲۶/۱۱/۱۰ · شاخه: `arena/5ac72d50-crushed-stone-and-sand-product`

پرسش کاربر:

> «یک یا دو دور قبل من وسط کارت دکمه ستاپ را زدم در حالی که تو کار می‌کردی —
> آیا چیزی از آن دور نیمه‌کاره نمانده است یا به چیزی آسیب نرسیده است؟»

پاسخ کوتاه: **هیچ کاری نیمه‌کاره نمانده و به داده یا کد آسیب نرسیده** — ولی
بازرسی همین سؤال یک دسته باگ واقعی رو کرد: **تست‌هایی که در ماشین من سبز و در
کلون تازه قرمز بودند.** یعنی «سبز بودن» من تضمینی نبود.

---

## ۱) بررسی سلامت (چیزهایی که سنجیده شد)

| بررسی | نتیجه |
|---|---|
| `git status` | درخت کار تمیز، هیچ فایل نیمه‌نوشته/`.orig`/`.rej`/`.bak` نیست |
| پروسه‌های جامانده | یک سرور ابزار لایسنس از تست زنده‌ی دور ۳۶ زنده مانده بود ← بسته شد |
| فایل‌های خالی/ناقص | فقط سه `-wal` خالی SQLite (طبیعی) |
| کامیت‌ها | `aaec272` (دور ۳۵) و `c88f864` (دور ۳۶) کامل و پوش‌شده؛ هیچ تغییر کامیت‌نشده |
| فایل‌های کلیدی | `.gitattributes`، `tools/shared/tool-server.mjs`، تست جدید، هر دو سند — همه tracked |
| داده | `data/farday.db` دست‌نخورده؛ هیچ تستی روی داده‌ی واقعی ننوشت |
| CRLF در کلون تازه | درست: `git ls-files --eol` → `i/lf w/crlf attr/text eol=crlf` |

> نکته‌ی فنی: git فایل `.cmd` را **با LF در آبجکت** نگه می‌دارد و هنگام
> checkout آن را به CRLF تبدیل می‌کند. این رفتار درست است، ولی تست دور ۳۶
> CRLF را روی **دیسک** می‌سنجید؛ در کلون تازه هم درست است (آزمایش شد)، پس
> آن تست سالم است.

## ۲) باگ‌های پیدا‌شده در بازرسی

### باگ ۱ — تست «هر دو فایل کلید مُهر در مخزن هست» کاذب بود

`src-tauri/seal/reset-key.txt` در `.gitignore` است (کلید صفر کردن، مثل کلید
خصوصی لایسنس، نباید در گیت باشد). تست «فایل روی دیسک هست» را می‌سنجید:

* در ماشین من (فایل موجود) → ✔
* در کلون تازه → ✘ **قرمز**

یعنی تست، رازِ کمیت را می‌سنجید، نه قرارداد را. اصلاح: «کلید عمومی در گیت
هست» + «`.gitignore` کلید صفر کردن را دور نگه می‌دارد» + «نبودش ساخت را
نمی‌شکند (build.rs فقط هشدار می‌دهد)».

### باگ ۲ — `api/**/*` به عنوان «الگوی خالی که ساخت را می‌شکند» گزارش می‌شد

`src-tauri/api` یک **محصول ساخت** است (`desktop:build` می‌سازدش). در کلون
تازه وجود ندارد، ولی `release-check` و `tauri-src` آن را مثل یک خطا گزارش
می‌کردند. اصلاح: محصول‌های ساخت (`api/`, `tools/`) از «الگوی خالی» جدا شدند
و به‌جایش **هشدار** داده می‌شود؛ بررسی وجود فایل فقط وقتی اجرا می‌شود که
محصول ساخته شده باشد.

### باگ ۳ — پیام گمراه‌کننده‌ی تست مهاجرت

در کلون تازه، `release-check` می‌گفت «تست مهاجرت یا بسته نشده یا ناکام دارد»
(سه احتمال در یک جمله، بدون راه‌حل). اصلاح: حالت «بسته ساخته نشده» جدا شد و
راه‌حل دقیق می‌دهد: `npm run build -w @farday/api`.

### باگ ۴ — `paths.test.mjs` هم به محصول ساخت وابسته بود

بررسی «باینری در ساختار بسته پیدا می‌شود» بدون ساخت بسته قرمز می‌شد. حالا
همیشه «مسیر جست‌وجو درست است» بررسی می‌شود (اصل باگ) و بررسی باینری فقط
وقتی که بسته ساخته شده باشد.

### باگ ۵ — «چرا تست قرمز است؟» دیر معلوم می‌شد

`npm test` در کلون تازه چند سوئیت را سبز می‌کرد و بعد با «اول
`npm run build -w @farday/api`» می‌مرد. حالا `scripts/preflight.mjs` **قبل از
هر تستی** می‌گوید چه چیزی لازم است، چه چیزی اختیاری است و با چه دستوری
درست می‌شود:

```
— پیش‌پرواز —
  ✔ وابستگی‌ها
  ✔ بسته‌ی API (تست‌ها به آن نیاز دارند)
  ⚠ بسته‌ی دسکتاپ نیست (اختیاری) — npm run desktop:build
```

## ۳) اعتماد: آزمایش کلون تازه

```
git clone . /tmp/clean-clone
npm install            # (در ساندباکس از node_modules موجود کاپی شد)
npm run build -w @farday/api
npm test
```

| مرحله | نتیجه |
|---|---|
| `npm test` **قبل** از اصلاحات | **exit 1** — ۳ ناکامی (`paths`, `tauri-src` ×۲) و `release-check` هم شکست |
| `npm test` **بعد** از اصلاحات | **exit 0** — ۲۱۰۷ خط ✔، ۰ ناکام |
| `release-check` در کلون تازه | فقط «بسته‌ی API ساخته نشده» با راه‌حل روشن (رفتار درست) |

در ماشین کاری (با بسته‌ی ساخته‌شده): `npm test` → exit 0، **۲۱۱۲ خط ✔**،
۰ ناکام؛ `release:check` → exit 0.

## ۴) چه چیزی هنوز «نیمه‌کاره» است (صادقانه)

هیچ چیز از کارِ قبلی نیمه‌کاره نمانده. ولی سه شکاف شناخته‌شده باقی است که در
دور ۳۶ هم گفته شد و هنوز باز است:

1. **ویندوز/Rust در ساندباکس نیست** — `start.cmd` و `.msi` واقعی اجرا نشدند.
2. **کلید صفر کردن (`reset-key.txt`) روی این ماشین هست ولی در گیت نیست** —
   اگر روی کمپیوتر دیگر بیلد بگیرید، ابزار «صفر کردن» روی نسخه‌ی مُهرشده با
   پیام «این نسخه مُهر نشده» کار نمی‌کند. این طرحِ عمدی است، ولی باید بدانید.
3. **شبیه‌سازی `glob` جای `tauri build` را نمی‌گیرد** — اولین بیلد ویندوز
   باید تأیید کند.
