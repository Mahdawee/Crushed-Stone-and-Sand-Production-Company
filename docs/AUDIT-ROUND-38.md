## باگ: `PUT /lookups/:id` قلم را بی‌صدا غیرفعال می‌کرد

بقیه‌ی مسیرها (`customers`, `employees`, `expenses`, `receipts`, `sales`,
`company`, `machinery`) همه این شکل را دارند:

```ts
body?.x === undefined ? String(existing.x ?? '') : String(body.x ?? '')
```

ولی `lookups` این‌طور بود:

```ts
name, body.extra || '', Number(body.sortOrder) || 0, body.active ? 1 : 0, lid
```

یعنی سه فیلد از **بدنه** خوانده می‌شد، نه از ردیف موجود. نتیجه‌ی عملی:

| درخواست | چه اتفاقی می‌افتاد |
|---|---|
| `PUT /lookups/12 { name: "شن" }` | `extra` پاک می‌شد |
| همان درخواست | `sortOrder` = ۰ → قلم به **بالای** فهرست می‌پرید |
| همان درخواست | `active` = ۰ → قلم **غیرفعال** می‌شد |

اثر سوم بدترین است: قلم از همه‌ی فهرست‌های انتخاب (فروش، مصرف، رسید) حذف
می‌شد، در گزارش‌ها به‌عنوان مقدار «ناشناخته» می‌آمد، و کاربر فکر می‌کرد
«فقط اسمش را عوض کردم». **ویرایش یک نام، داده را از دسترس خارج می‌کرد** —
یک باگ خاموش با اثر داده‌ای.

## اصلاح

```ts
const extra = body?.extra === undefined ? String(cur.extra ?? '') : String(body.extra ?? '');
const sortOrder = body?.sortOrder === undefined ? Number(cur.sortOrder) || 0 : Number(body.sortOrder);
if (!Number.isFinite(sortOrder)) throw new HttpException('ترتیب باید عدد باشد.', 400);
const active = parseActive(body?.active);   // boolean | 0/1 | "true"/"false" | "فعال"/"غیرفعال"
```

* `undefined` = «همان مقدار قبلی».
* `active` حالا چند شکل را می‌فهمد (boolean، ۰/۱، رشته) و مقدار ناشناخته را
  نادیده می‌گیرد — قبلاً رشته‌ی `"false"` **فعال** حساب می‌شد (truthy)، یعنی
  یک تله‌ی دیگر در همان خط.
* مقدار نامعتبر `sortOrder` حالا ۴۰۰ می‌گیرد، نه ۰.

## تست دائمی (این بار واقعاً گرفته می‌شود)

`apps/api/test/partial-edit.test.js` از دور ۳۴ وجود داشت اما **فهرست‌ها در آن
جا افتاده بود** — همین باعث شد باگ تا امروز زنده بماند. ۱۲ بررسی اضافه شد:

```
— فهرست‌ها: ویرایش نام، قلم را غیرفعال/صفر نمی‌کند —
  ✔ ویرایش فقط نام، موفق است
  ✔ نام تازه نوشته شد
  ✔ «extra» پاک نشد
  ✔ «sortOrder» صفر نشد
  ✔ قلم **غیرفعال نشد**
  ✔ قلم هنوز در فهرست فعال‌ها هست
  ✔ غیرفعال‌کردن صریح کار می‌کند
  ✔ قلم غیرفعال از فهرست فعال‌ها رفت
```

**اعتبار تست:** با برگرداندن کد قدیمی، همین تست ۴ ناکامی می‌دهد:

```
✘ «extra» پاک نشد
✘ «sortOrder» صفر نشد → 0 ≠ 15
✘ قلم **غیرفعال نشد** → false
✘ قلم هنوز در فهرست فعال‌ها هست
⛔ 83 موفق، 4 ناکام
```

یعنی تست واقعاً همان باگ را می‌گیرد، نه اینکه همیشه سبز باشد.
