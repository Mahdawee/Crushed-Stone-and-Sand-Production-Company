# پرسش‌های متداول

**آیا به انترنت نیاز دارم؟**
نه. نصب، اجرا، فونت‌ها و دیتابیس همه محلی‌اند.

**معلومات کجا ذخیره می‌شود؟**
`%APPDATA%\af.farday.roshan\farday.db` — یک فایل SQLite. برای انتقال همان فایل (یا پشتیبان) کافی است.

**چند کمپیوتر می‌توانند همزمان استفاده کنند؟**
نسخه فعلی برای **یک کمپیوتر** طراحی شده (مثل برنامه صندوق فروشگاهی). برای شبکه داخلی،
بعداً می‌توان API را روی یک کمپیوتر میزبان اجرا کرد — ساختار آماده است.

**تاریخ‌ها را شمسی وارد کنم یا میلادی؟**
هر کدام که در تنظیمات انتخاب شده. می‌توانید با ارقام دری هم بنویسید: `۱۴۰۵/۰۸/۱۹`.
اگر تقویم را عوض کنید، معلومات پاک نمی‌شود؛ فقط نمایش عوض می‌شود.

**چرا مبلغ دالری در سود/زیان نیست؟**
طبق تصمیم سیستم، مبلغ دالری جدا نگه داشته می‌شود و سود/زیان فقط با افغانی حساب می‌شود.

**بدهی مشتری چطور حساب می‌شود؟**
`بدهی اولیه + مجموع فروشات قرضه − رسیدات (به جز رسیدهایی که «از درک = امانت» دارند)`.

**رسید «امانت» چیست؟**
پولی که مشتری به عنوان امانت می‌سپارد (هنوز تسویه بل نیست) و از بدهی کم نمی‌شود.

**شماره بل را می‌توانم دستی بزنم؟**
بله، ولی سیستم تضمین می‌کند شماره تکراری ثبت نشود؛ شمارنده خودکار بعد از آخرین شماره ادامه می‌دهد.

**کارمندی که رفته را حذف کنم؟**
اگر سابقه معاش دارد، حذف نمی‌شود (برای حفظ اسناد). وضعیت او را «غیر فعال» کنید.

**وقتی چیزی را حذف می‌کنم، در حساب‌ها و گزارشات هم اثر می‌کند؟**
بله — و همین درست است. ردیفی که به «سطل بازیافت» می‌رود **در هیچ محاسبه‌ای شمرده نمی‌شود**:
نه در مانده‌ی حساب مشتری، نه در فروشات، نه در صندوق، نه در مصارف و معاش، نه در حضور و غیاب
و نه در خروجی اکسل. داده پاک نمی‌شود و با دکمه‌ی «بازگرداندن» همان ردیف با همان شناسه برمی‌گردد،
پس همه‌ی محاسبات دوباره دقیقاً مثل قبل می‌شوند.

**چرا کارمند/مشتری حذف نمی‌شود؟**
اگر سابقه داشته باشد (معاش، حضور و غیاب، بل فروش، رسید) برنامه اجازه نمی‌دهد تا اسناد قدیمی
«یتیم» نشوند؛ به‌جای حذف، وضعیتش را «غیر فعال» کنید. حذفِ کارمند یا مشتریِ بدون سابقه هم
«نرم» است و از سطل بازیافت برمی‌گردد.

**رمز admin را فراموش کردم.**
با یک کاربر مدیر دیگر وارد شوید. اگر هیچ راهی نبود، فایل دیتابیس را پشتیبان بگیرید و
از `apps/api/dist/cli/reset.js` استفاده کنید (کاربران و تنظیمات محفوظ می‌ماند) — یا از پشتیبان قبلی بازگردانی کنید.

**وقتی آدرس `/api` را در مرورگر باز می‌کنم پیام `Cannot GET /api` می‌آید.**
این آدرس **سرویس داخلی** برنامه است، نه صفحه برنامه. از نسخه فعلی، همین آدرس یک صفحه راهنمای دری
با دکمه «رفتن به برنامه» نشان می‌دهد. آدرس درست خود برنامه `http://127.0.0.1:4317/` است
(در حالت توسعه: `http://localhost:5173/`). اگر باز هم متن خام دیدید، نسخه قدیمی API در حال
اجراست — `npm run build -w @farday/api` و بعد برنامه را دوباره باز کنید.

**نصب‌کننده ویندوز را چطور بسازم؟**
`npm run doctor` → `npm run desktop:setup` → `npm run desktop:build`
(راهنمای کامل: `docs/TAURI-BUILD.md`). کمپیوتر شرکت فقط فایل `*-setup.exe` را می‌خواهد.

**خطای `{"message":"Cannot GET /","error":"Not Found","statusCode":404}`**
یعنی رابط کاربری ساخته نشده است (`apps/web/dist` خالی است) و API چیزی برای نمایش در `/` ندارد.
دو دلیل رایج روی ویندوز:

1. `npm install` اجرا نشده یا نیمه‌کاره مانده → در پوشه پروژه: `npm install`
2. خروجی build از گیت نیامده (پوشه `dist` در گیت نیست — این درست است) →
   `npm run build` و بعد نسخه دسکتاپ: `npm run desktop:dev`

از نسخه فعلی، باز کردن `/` بدون رابط، صفحه دری «رابط کاربری ساخته نشده» را با همین راه‌حل
نشان می‌دهد (کد ۵۰۳ روی HTTP، ولی یک صفحه خوانا نه JSON خام). آدرس‌های ناموجود هم در مرورگر
همان صفحه راهنما را می‌دهند؛ کلاینت‌های JSON همان `404` معمولی را می‌گیرند.

**صفحه سفید می‌ماند / «سرویس محلی در دسترس نیست»**
برنامه را ببندید، در Task Manager اگر `node.exe` مانده آن را ببندید و دوباره باز کنید.
اگر ادامه یافت، از `docs/INSTALL-WINDOWS.md` بخش «اگر برنامه باز نشد» استفاده کنید.

**پشتیبان چند وقت یک بار؟**
هر هفته یک بار + قبل از هر تغییر بزرگ. ۳۰ فایل آخر خودکار نگه داشته می‌شود.

## «بیانیه» و «پیش‌پرداخت» — یکی شدند

«بیانیه» و «پیش‌پرداخت» در واقع **یک چیز** بودند و دو نام داشتند. از نسخه‌ی فعلی فقط
**«بیانیه»** می‌ماند.

* سندهای قدیمی که با «پیش پرداخت» یا «بیانه» ثبت شده‌اند **دست‌نخورده** می‌مانند: هنگام
  باز شدن برنامه یک بار به نام رسمی «بیانیه» تبدیل می‌شوند (مبلغ، تاریخ و مشتری تغییر نمی‌کند).
* ردیف‌های اضافی فهرست کشویی **حذف نمی‌شوند**، فقط غیرفعال می‌شوند — مثل بقیه‌ی حذف‌های برنامه.
* مانده‌ی هیچ مشتری با این تغییر عوض نمی‌شود: تصمیم «این رسید از بدهی کم می‌شود یا نه» از یک
  جای واحد (`apps/api/src/common/domain.ts`) گرفته می‌شود و همان رفتار قبلی است (فقط «امانت»
  از بدهی کم نمی‌کند).

## «مربوط» یعنی شاخه‌ی مصرف

«مربوط» یک طرف حساب جداگانه نیست؛ **شاخه‌ی مصرف** است — همان طرفی که هزینه یا کرایه به آن
تعلق دارد: باربری، دمترک، اکستر، یا شخص.

| کجا | «مربوط» چه معنایی دارد |
| --- | --- |
| بل فروش | کرایه‌ی حمل به این شاخه تعلق می‌گیرد |
| مصرف | طرف حساب سند همین شاخه است |
| رسید | پول از این شاخه آمده و بل مشتری را تسویه می‌کند |

در «راپورهای تفصیلی» یک تب تازه هست: **مربوط (شاخه مصرف)**. برای هر شاخه، در یک جدول
می‌بینید: تعداد بل فروش و مجموع کرایه، تعداد و مبلغ مصرف، و تعداد و مبلغ رسید. ردیف
«بدون شاخه» سندهایی را نشان می‌دهد که شاخه برایشان انتخاب نشده — تا جمع کل با جمع اسناد بخواند.
