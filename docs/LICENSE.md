# سیستم لایسنس فردای روشن

امضای دیجیتال **Ed25519** · قفل دستگاه · قفل ساعت (تلورانس ۲۴ ساعت) · کاملاً آفلاین

---

## صفر) ابزار گرافیکی (پیشنهادی)

```bash
npm run license:ui
```

→ `http://127.0.0.1:4321`

یک صفحه‌ی کامل فارسی و راست‌به‌چپ که همه‌ی کارها را با کلیک انجام می‌دهد:

| بخش | کار |
|---|---|
| ۱) جفت‌کلید | ساخت کلید، نمایش اثر انگشت، کاپی کلید عمومی، بررسی هم‌خوانی با کلید داخل بسته |
| ۲) صدور لایسنس | نام مشتری، نوع دوره، تاریخ شمسی یا میلادی، کلید دستگاه، صندلی، یادداشت → متن لایسنس آماده‌ی کاپی |
| ۳) دفتر لایسنس‌ها | فهرست با وضعیت (فعال/منقضی/باطل)، کاپی متن هر لایسنس، باطل‌کردن |
| ۴) بازرسی | متن لایسنس را بچسبانید: امضا معتبر است؟ منقضی است؟ برای کدام دستگاه؟ |

سرور ابزار فقط روی `127.0.0.1` گوش می‌دهد، کلید خصوصی را **هرگز** از طریق
HTTP برنمی‌گرداند و برای هر تغییر توکن CSRF می‌خواهد (یک تب مخرب در مرورگر
نمی‌تواند برای شما لایسنس صادر کند).

همان کارها از خط فرمان هم هست (`npm run license:issue …`) — برای اتوماسیون.

## الف) یک‌بار برای همیشه: ساخت کلید

```bash
npm run license:keygen
```

این دستور:

| فایل | چیست | کجا |
|---|---|---|
| `license-keys/private.key` | **کلید خصوصی** — با آن لایسنس امضا می‌شود | فقط روی کمپیوتر خودتان |
| `license-keys/public.key` | کلید عمومی (کاپی) | — |
| `src-tauri/public-key/farday-public.b64` | کلید عمومی که **داخل بسته** می‌رود | در گیت، همراه نسخه |
| `apps/api/public-key/farday-public.b64` | همان کلید برای اجرای محلی | در گیت |

> **کلید خصوصی هرگز نباید کامیت شود، جایی آپلود شود یا برای مشتری برود.**
> `license-keys/` از قبل در `.gitignore` است.

- **گم شد؟** لایسنس‌های صادرشده معتبر می‌مانند، ولی نمی‌توانید لایسنس تازه صادر کنید.
  پس یک کاپی از `license-keys/private.key` روی فلش/کاغذ چاپ‌شده نگه دارید.
- **لو رفت؟** هر کسی می‌تواند لایسنس بسازد → `npm run license:keygen -- --force`
  (کلید تازه) و نسخه‌ی جدید برنامه را بسازید. لایسنس‌های قبلی باطل می‌شوند.

بعد از keygen، برنامه را با کلید تازه بسازید:

```bash
npm run desktop:build
```

## ب) گرفتن کلید دستگاه از مشتری

مشتری برنامه را باز می‌کند → صفحه‌ی **لایسنس** باز می‌شود → دکمه‌ی **کاپی** کنار
«کلید دستگاه». چیزی مثل:

```
A74PA-AW6C7-UAB99-PAPJU-VQWQW
```

همین کد کافی است. (از داخل برنامه: `GET /api/license/device` هم همان را می‌دهد.)

کلید دستگاه از `MachineGuid` ویندوز + UUID تخته‌مادر + نام کمپیوتر/کاربر ساخته
می‌شود و **فقط به شکل یک هش ۲۵ نویسه‌ای** بیرون می‌رود؛ هیچ اطلاعات خامی از
کمپیوتر مشتری جایی نمی‌رود.

## ج) صدور لایسنس

```bash
# سالانه (۳۶۵ روز از امروز)
npm run license:issue -- --customer "شرکت سنگ و ریگ الف" --kind yearly \
  --machine A74PA-AW6C7-UAB99-PAPJU-VQWQW

# ماهوار (۳۰ روز)
npm run license:issue -- --customer "…" --kind monthly --machine …

# ابد (بدون تاریخ پایان — قفل دستگاه همچنان فعال است)
npm run license:issue -- --customer "…" --kind perpetual --machine …

# تاریخ دلخواه (شمسی یا میلادی، هر دو پذیرفته می‌شود)
npm run license:issue -- --customer "…" --kind custom \
  --start 1405/08/19 --end 1406/08/19 --machine …

# آزمایشی ۷ روز / فقط قفل دستگاه
npm run license:issue -- --customer "…" --kind trial
npm run license:issue -- --customer "…" --kind machine --machine …

# چند کاربر هم‌زمان + یادداشت + فایل خروجی دلخواه
npm run license:issue -- --customer "…" --kind yearly --machine … --seats 3 \
  --note "تلفن ۰۷۰…" --out licenses/company-a.lic

# خروجی JSON (برای اتوماسیون)
npm run license:issue -- --customer "…" --kind yearly --machine … --json
```

خروجی، یک بلوک متنی است:

```
-----BEGIN FARDAY LICENSE-----
FR-1
eyJ2IjoxLCJpZCI6…
gePv0Kr3egwytQ8quDB1sfjk…
-----END FARDAY LICENSE-----
```

همین را برای مشتری می‌فرستید (واتساپ، ایمیل، کاغذ). او در صفحه‌ی لایسنس
جای‌گذاری می‌کند و «فعال‌سازی» را می‌زند. **بدون انترنت.**

هر لایسنس صادرشده در `license-keys/issued.json` ثبت می‌شود:

```bash
npm run license:list                 # فهرست با وضعیت فعال/منقضی/باطل
npm run license:verify -- --file license-keys/FR-LIC-2026-0001.lic
npm run license:revoke -- --id FR-LIC-2026-0001     # علامت «باطل» در دفتر
```

## د) درون لایسنس چه چیزی امضا می‌شود؟

```json
{
  "v": 1,
  "id": "FR-LIC-2026-0001",
  "customer": "شرکت سنگ و ریگ الف",
  "kind": "yearly",
  "start": "2026-11-10",
  "end": "2027-11-09",
  "machineKey": "A74PA-AW6C7-UAB99-PAPJU-VQWQW",
  "seats": 1,
  "note": "",
  "issuedAt": "2026-11-10T13:20:00.000Z"
}
```

امضای Ed25519 روی **همان رشته‌ی base64** زده می‌شود. اگر مشتری یک نویسه را عوض
کند (تاریخ پایان، نام، کلید دستگاه) امضا باطل می‌شود و برنامه باز نمی‌شود.

## ه) چهار لایه‌ی قفل — و اینکه هر کدام چه چیزی را می‌گیرد

| لایه | چه چیزی را می‌گیرد | چه چیزی نمی‌گیرد |
|---|---|---|
| **امضای Ed25519** | دست‌کاری متن لایسنس، ساختن لایسنس بدون کلید خصوصی | وصله‌کردن فایل اجرایی برنامه |
| **قفل دستگاه** | کاپی‌کردن لایسنس روی کمپیوتر دوم | عوض‌کردن سخت‌افزار/نصب مجدد ویندوز (کلید عوض می‌شود → لایسنس تازه لازم است، این عمدی است) |
| **قفل ساعت** | عقب‌بردن ساعت برای زنده‌کردن لایسنس منقضی، جلوبردن ساعت | — |
| **مُهر کلید در باینری** | عوض‌کردن فایل کلید عمومی با کلید خودِ مشتری | وصله‌کردن فایل اجرایی (بند ط) |

### قفل ساعت چطور کار می‌کند

1. هر بار که برنامه باز می‌شود «زمان دیده‌شده» ثبت می‌شود.
2. بزرگ‌ترین زمان دیده‌شده = **مرجع**.
3. اگر ساعت ویندوز بیش از **۲۴ ساعت** با مرجع فاصله داشته باشد → برنامه قفل
   می‌شود و پیام فارسی می‌دهد (عقب یا جلو، هر دو).
4. «اکنون» هرگز از مرجع عقب‌تر حساب نمی‌شود: پس عقب‌بردن ساعت، لایسنس منقضی
   را **زنده نمی‌کند** (برنامه همان تاریخ پایان امضاشده را می‌سنجد).
5. رکورد ساعت در **دو جا** (دیتابیس `LicenseClock` و فایل `license.clock`) با
   مهر HMAC ذخیره می‌شود. پاک‌کردن یکی بی‌فایده است؛ پاک‌کردن هر دو یعنی
   «اولین اجرا» — و آن هم تاریخ پایان امضاشده را عوض نمی‌کند.
6. اگر واقعاً ساعت اشتباه بوده (باتری مادربرد، تنظیم ویندوز): ساعت را درست
   کنید، در صفحه‌ی لایسنس تیک «ساعت را درست کرده‌ام» را بزنید و همان لایسنس
   را دوباره وارد کنید. مرجع هم‌تراز می‌شود، ولی تاریخ پایان جلو نمی‌رود.

> **صادقانه:** هیچ برنامه‌ای که روی کمپیوتر کاربر نصب می‌شود در برابر
> وصله‌کردن باینری «مطلقاً» مصون نیست. هدف این طراحی این است که دور زدن
> نیاز به **دست‌کاری فنی فایل اجرایی** داشته باشد، نه یک کلیک (تغییر ساعت،
> تغییر تاریخ، کاپی متن). برای همین کلید خصوصی هرگز در بسته نیست و همه‌ی
> بررسی‌ها در سرور محلی (Node) انجام می‌شود، نه در رابط کاربری.

## و) دوره‌ی آزمایشی

اگر هیچ لایسنسی روی دستگاه نباشد، برنامه **۷ روز** به‌صورت آزمایشی کار می‌کند
(همان قفل زمان روی دوره‌ی آزمایشی هم اعمال می‌شود). بعد از آن فقط صفحه‌ی
لایسنس باز است.

برای تغییر طول دوره‌ی آزمایشی: `TRIAL_DAYS` در
`apps/api/src/common/license-state.ts`.

## ز) پرسش‌های رایج

**مشتری ویندوز را از نو نصب کرد و کلید دستگاه عوض شد.**
کلید تازه را بگیرید و لایسنس تازه صادر کنید (همان مشتری، همان تاریخ پایان).
در دفتر لایسنس‌ها یادداشت بزنید.

**مشتری می‌گوید «لایسنس را وارد کردم، باز هم قفل است».**
`GET /api/license/status` یا بخش «لایسنس» در تنظیمات را ببینید: پیام دقیقاً
می‌گوید کدام لایه رد کرده است (امضا / دستگاه / ساعت / تاریخ). برای قفل ساعت
راه‌حل بند «ه» را بگویید.

**دو کمپیوتر در یک دفتر.**
برای هر کمپیوتر یک لایسنس با کلید دستگاه خودش. `--seats` فقط تعداد کاربران
هم‌زمان را ثبت می‌کند (نمایشی).

**می‌خواهم لایسنس را قبل از تحویل ببینم.**
```bash
npm run license:verify -- --file license-keys/FR-LIC-2026-0001.lic
```

## ط) می‌تواند دور بزند؟ — پاسخ صادقانه

کاربر نصب‌کننده **آفلاین** است و به فایل‌های خودش دسترسی کامل دارد. پس سؤال
درست این نیست «آیا می‌شود دور زد؟» بلکه «هزینه‌ی دور زدن چقدر است؟».

| روش دور زدن | نتیجه |
|---|---|
| تغییر متن لایسنس (تاریخ، نام، دستگاه) | ❌ امضای Ed25519 باطل می‌شود |
| ساختن لایسنس بدون کلید خصوصی | ❌ عملاً ناممکن (امنیت Ed25519) |
| کاپی لایسنس روی کمپیوتر دیگر | ❌ قفل دستگاه رد می‌کند |
| عقب‌بردن ساعت ویندوز | ❌ «اکنون» هرگز از مرجع عقب‌تر نیست |
| جلو‌بردن ساعت برای رد کردن انقضا | ❌ قفل ساعت (تلورانس ۲۴ ساعت) |
| پاک‌کردن `license.clock` | ❌ نسخه‌ی دوم مهر در دیتابیس؛ و تاریخ پایان امضاشده است |
| پاک‌کردن دیتابیس | ❌ لایسنس از فایل `license.key` خوانده می‌شود؛ و باز هم تاریخ پایان امضاشده |
| عوض کردن فایل کلید عمومی با کلید خودش | ❌ کلید از **داخل باینری** خوانده می‌شود؛ و `FD_*` فقط در حالت توسعه اثر دارد |
| گذاشتن `license-public-key.txt` در پوشه‌ی داده | ❌ برنامه هیچ کلیدی از پوشه‌ی داده نمی‌خواند |
| `set FD_MACHINE_KEY=…` | ❌ فقط با `FD_LICENSE_DEV=1` (که در نسخه‌ی نصب‌شده نیست) |
| وصله‌کردن فایل اجرایی (hex edit) | ⚠ **ممکن است** — این تنها راه واقعی است |

### پس آن یک راه را چطور تنگ کردیم؟

1. کلید عمومی **داخل فایل اجرایی** مُهر شده است (نه فایل کنارش)؛ عوض‌کردنش
   یعنی وصله‌کردن باینری، نه Notepad.
2. بررسی لایسنس در **سرویس داخلی** انجام می‌شود و نگهبان سراسری همه‌ی
   مسیرهای داده را می‌بندد؛ فقط صفحه‌ی لایسنس باز است.
3. هیچ درِ پشتی محیطی در نسخه‌ی نصب‌شده وجود ندارد.
4. دو نسخه از «ساعت مرجع» (دیتابیس + فایل) و دو نسخه از لایسنس
   (دیتابیس + فایل) نگه داشته می‌شود.

### چه چیزی را نمی‌توانیم تضمین کنیم (و هیچ‌کس نمی‌تواند)

برنامه‌ای که روی کمپیوتر کاربر اجرا می‌شود، در نهایت در اختیار کاربر است؛
با دیباگر/hex-editor می‌شود شرط‌ها را حذف کرد. بدون سرور آنلاین (که خواسته‌ی
شما نبود) نمی‌شود بیشتر از این تضمین کرد. کاری که شده: دور زدن از «تغییر
ساعت / تغییر تاریخ / کاپی متن» به «مهندسی معکوس فایل اجرایی» منتقل شده است.
