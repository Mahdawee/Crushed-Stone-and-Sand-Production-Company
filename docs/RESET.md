# صفر کردن سیستم — تحویل آک به مشتری

ابزار بیرونی در `tools/reset-ui` · صفحه‌ی گرافیکی + اجراکننده‌ی ویندوز/لینوکس + خط فرمان
**هیچ داده‌ای بدون تأیید صریح و پشتیبان پاک نمی‌شود.**

---

## ۱) چرا بیرون از برنامه است

خواسته‌ی مالک: «این را به حیث یک ابزار بیرونی در پوشه‌ی tools می‌خواهم، نه در
داخل برنامه.»

- **کاربر نهایی** در برنامه هیچ دکمه‌ای برای پاک‌کردن کل داده نمی‌بیند؛ یک
  کلیک اشتباه، داده‌ی یک سال را نابود می‌کند.
- ابزار بیرونی **هشدار کامل** می‌دهد، فهرست چیزی که پاک می‌شود را نشان می‌دهد و
  دو تأیید می‌گیرد.

نکته‌ی فنی: دیتابیس در حال اجرا قفل است؛ پاک‌کردن فایل از بیرون، برنامه را با
داده‌ی **نیمه‌پاک** رها می‌کند. برای همین دو حالت داریم:

| حالت | چه می‌شود |
|---|---|
| برنامه **بسته** (حالت عادی تحویل) | هسته‌ی مستقل `reset-core.mjs` مستقیم روی فایل کار می‌کند |
| برنامه **باز** | ابزار از راه `POST /system/reset` (با ورود مدیر) همان کار را می‌کند |

ابزار خودش تشخیص می‌دهد و در صفحه می‌گوید کدام حالت است. اگر نمونه‌ی دیگری از
برنامه روی همان کمپیوتر به **داده‌ی دیگری** وصل باشد، آفلاین حساب می‌شود
(وگرنه ممکن بود دیتابیس اشتباهی صفر شود).

---

## ۲) اجرا

### ویندوز (اجراکننده)
```
tools\reset-ui\start.cmd
```
دوبار کلیک کافی است. اگر `node.exe` همراه نسخه‌ی نصب‌شده باشد از همان استفاده
می‌کند؛ وگرنه پیام روشن می‌دهد که Node لازم است.

### لینوکس/مک
```bash
./tools/reset-ui/start.sh          # یا: npm run reset:ui
```

### خط فرمان (تحویل با اسکریپت)
```bash
npm run reset -- --info                              # وضعیت داده، بدون تغییر
npm run reset -- --yes --confirm "صفر کردن" \
  --reason "تحویل به مشتری — شرکت سنگ بامیان" --operator "نام شما"
```

## ۳) کلید «صفر کردن» — چرا لازم است

ابزار می‌تواند همه‌ی داده را پاک کند، پس باید ثابت کند مالکِ همین نسخه است.

1. کلید **یک بار** برای پروژه ساخته می‌شود و در git نیست:
   ```bash
   npm run reset:key -- --ensure
   ```
   خروجی در `src-tauri/seal/reset-key.txt` و کاپی مالک در `license-keys/reset-key.txt`.
2. هنگام ساخت، `build.rs` آن را **داخل فایل اجرایی مُهر** می‌کند
   (`SEALED_RESET_KEY` + اثر انگشت SHA-256).
3. مالک کلید را از نسخه‌ی نصب‌شده می‌گیرد:
   ```
   Farday Roshan.exe --cli --print-reset-key
   ```
   یا از صفحه‌ی خطای برنامه → دکمه‌ی «نمایش کلید صفر کردن داده».
4. همان کلید را در کادر ابزار می‌چسباند.

> اگر نسخه‌ای **بدون** این کلید ساخته شود، ابزار صفر کردن روی آن کار نمی‌کند و
> صریح می‌گوید چرا (نه «خطای نامشخص»). این عمدی است: کلید عمومیِ لو رفته یعنی
> هر کسی می‌تواند داده‌ی مشتری را پاک کند.

کلید صفر کردن **جدا** از کلید لایسنس است: اختیار «نصب و تحویل» نباید همان
اختیار «امضای لایسنس» باشد.

## ۴) دقیقاً چه چیزی پاک می‌شود

1. ردیف‌های کاری: فروشات، رسیدات، مصارف، معاشات، حضور و غیاب، کارمندان، مشتریان.
2. سطل بازیافت و لاگ فعالیت (ردّ مشتری قبلی نباید بماند).
3. فهرست‌های سفارشی، ماشینری، مشخصات شرکت و تنظیمات (به پیش‌فرض برمی‌گردند).
4. لایسنس فعال، پشتیبان‌های قبلی و درخواست‌های تمدید.

و چه چیزی **بازسازی** می‌شود تا سیستم قابل استفاده باشد:

- کاربر مدیر (`admin / admin123` — اگر قبلاً کاربری نبود) — در گزارش نوشته می‌شود.
- «مشتری گذری (بدون حساب)» — تا بل فروش بدون مشتری همان لحظه ثبت شود.
- فهرست‌های پیش‌فرض (مواد، دسته‌های مصرف، منابع رسید، ماشینری) — برنامه در
  بالا آمدن بعدی خودش می‌سازد.

### پشتیبان
قبل از هر تغییری یک فایل `backups/pre-reset-<تاریخ>.db` ساخته و **سلامتش
بررسی** می‌شود؛ اگر ساخته نشود، صفر کردن انجام **نمی‌شود**. همین یک فایل
نگه داشته می‌شود (تنها راه برگشت) و بقیه‌ی پشتیبان‌ها پاک می‌شوند.

### گزارش
- `data/system-reset.json` — مهر با تعداد ردیف‌های پاک‌شده، اپراتور، دلیل، پشتیبان.
- `data/reset-history.log` — یک خط برای هر عملیات (تاریخچه).

## ۵) حفاظ‌ها

| حفاظ | چرا |
|---|---|
| تیک «می‌دانم برگشت‌ناپذیر است» | جلوگیری از کلیک اشتباه |
| تایپ عبارت `صفر کردن` | جلوگیری از اجرای ناخواسته/اسکریپتی |
| دو پنجره‌ی تأیید پشت سر هم | آخرین فرصت، با فهرست چیزی که پاک می‌شود |
| کلید مُهرشده | فقط مالک نسخه |
| پشتیبان اجباری + بررسی سلامت | هیچ‌وقت بدون راه برگشت |
| فقط `127.0.0.1` + CSRF + بررسی مبدأ | از شبکه قابل اجرا نیست |
| در حالت API: فقط نقش مدیر + فقط از خود کمپیوتر | کارمند عادی نمی‌تواند |

---

## ۶) بعد از تحویل

1. برنامه را باز کنید — فهرست‌های پیش‌فرض خودکار ساخته می‌شوند.
2. با `admin / admin123` وارد شوید و **رمز را عوض کنید**.
3. لایسنس مشتری جدید را فعال کنید (صفحه‌ی «لایسنس»).
4. اگر لازم شد، فایل پشتیبان `pre-reset-…db` را در جای مطمئن نگه دارید
   (برای خودتان، نه برای مشتری بعدی).
