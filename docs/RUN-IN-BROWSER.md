# اجرا در مرورگر (بدون نصب — برای آزمایش سریع)

دو راه وجود دارد:

## ۱) حالت توسعه (با hot-reload)

```bash
npm install
npm run dev          # API :4317  +  وب :5173
```
پس از چند ثانیه، ترمینال یک کارت چاپ می‌کند:

```
──────────────────────────────────────────────────────────
  برنامه آماده است — یکی از این آدرس‌ها را باز کنید:
  ➜  رابط کاربری :  http://localhost:5173/   (with hot reload)
  ➜  نسخه یک‌آدرس:  http://127.0.0.1:4317/   (نیاز به build دارد)
  ➜  سرویس API :     http://127.0.0.1:4317/api
  ➜  ورود:           admin / admin123
──────────────────────────────────────────────────────────
```

- در حالت توسعه، **رابط کاربری را Vite سرو می‌کند** (پورت ۵۱۷۳). پورت ۴۳۱۷ فقط سرویس است و اگر
  آن را در مرورگر باز کنید، شما را به همان ۵۱۷۳ هدایت می‌کند.
- `npm run dev` در ترمینال باز می‌ماند و لاگ‌های API + وب را با برچسب `[API]` و `[WEB]` نشان می‌دهد.
- پورت‌ها را عوض کنید: `FD_PORT=4400 FD_WEB_PORT=5200 npm run dev` (پروکسی Vite خودکار هم‌راستا می‌شود).
- با `Ctrl+C` هر دو پروسه با هم بسته می‌شوند.

## ۲) حالت «تک‌آدرس» (همان چیزی که در نسخه نصب‌شده اجرا می‌شود)

در این حالت خود API، فایل‌های ساخته‌شده React را هم سرو می‌کند؛ فقط یک پورت.

```bash
npm run build                # API + وب
node apps/api/dist/main.js   # http://127.0.0.1:4317
```

مزیت: دقیقاً همان رفتاری که پنجره دسکتاپ دارد (یک آدرس محلی، بدون Vite).

> اگر می‌خواهید برنامه از موبایل یا کمپیوتر دیگری در **شبکه داخلی** باز شود،
> `FD_HOST=0.0.0.0 node apps/api/dist/main.js` را اجرا کنید و آدرس
> `http://<IP کمپیوتر>:4317` را در مرورگر بزنید. (در ویندوز باید در Firewall اجازه بدهید.)
> برای استفاده معمولی شرکت، همین حالت کافی است — نه VPS، نه انترنت.

## متغیرهای محیطی

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `FD_PORT` | `4317` | پورت API و وب |
| `FD_HOST` | `127.0.0.1` | `0.0.0.0` برای دسترسی از شبکه داخلی |
| `FD_DATA_DIR` | `./data` | پوشه فایل دیتابیس و پشتیبان‌ها |
| `FD_DB_FILE` | — | مسیر دقیق فایل دیتابیس (اختیاری) |
| `FD_WEB_DIST` | — | مسیر فایل‌های build شده React (اختیاری) |
